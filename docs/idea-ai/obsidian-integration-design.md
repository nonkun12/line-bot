# アイデアAI × Obsidian 設計メモ

## 目的

LINE AI Secretary と既存の Obsidian Bridge を活用し、アイデアを捕捉・整理・関連付け・発展させ、必要に応じて開発候補へ変換する「アイデアAI」を段階的に構築する。

## 既存構成との接続

- Vault: `~/Documents/LINE AI Secretary`
- 現在の受け口: `LINE-Inbox.md`
- 既存 Bridge: `scripts/obsidian_mac_bridge.py`
- Obsidian Agent: `agents/obsidian/node.py` / `agents/obsidian/intents.py`
- 既存の安全策を維持し、Bridge は Mac 側から外向き HTTPS 接続する。Vault 自体をネットワークに公開しない。
- Mac が停止中でもアイデアが消えないよう、LINE 側の受付と Vault への実保存を別々の状態として扱う。

## MVP の動作

1. ユーザーが LINE または Obsidian から「アイデア: ...」を入力する。
2. 原文を保存対象として保持し、AIの推測と混同しない。
3. アイデアカードに ID、受付日時、原文、要約、カテゴリ、関連アイデア、未確認の仮説、次の小さな検証を記録する。
4. Vault には専用の `Ideas/Inbox/` 配下へ新規ノートとして保存する。既存ノートを上書きしない。
5. 類似候補はリンク候補として提示する。自動統合・原案の書き換えはしない。
6. 実装タスクへの変換は提案に留め、ユーザーの明示的な承認なしに自動実行・マージ・デプロイしない。

## ノート形式（案）

- `Ideas/Inbox/IDEA-<id>.md`: 原案と構造化カード
- `Ideas/Index.md`: アイデア一覧と状態
- `Ideas/Experiments.md`: 検証候補・結果へのリンク
- `Ideas/Connections.md`: アイデア間の関係メモ

各アイデアカードの項目:
- status: captured / exploring / testing / accepted / parked / rejected
- source: LINE / Obsidian / manual
- original: 原文
- summary: 要約（原案とは分離）
- category: 暫定分類
- related: 関連ノートへのリンク候補
- assumptions: 未検証の仮説
- next_experiment: 最小の検証案
- execution_approval: pending / approved / rejected

## AI の役割

- 発散: 別案、組み合わせ、反例、応用先を提案する。
- 収束: 価値、実現難度、コスト、リスク、検証可能性を明示する。
- 接続: 過去ノートの検索結果から関連候補を提案する。根拠のない「関連あり」を断定しない。
- 学習: 採用・保留・却下の理由を記録し、次回の提案に反映できるようにする。
- 実行: 実装タスクは明示承認後にのみ作成する。

## 無料・ローカル優先

- 有料 API を必須依存にしない。
- Mac が稼働中なら、既存の Bonsai 2 9B ローカルサーバーを任意の分析エンジンとして使える。
- Mac 停止中は捕捉・保存待ち・決定的な分類を継続し、ローカル推論が必要な分析は pending にする。モデル利用不可を成功扱いしない。
- 自動モデルダウンロードや有料サービスへのフォールバックは行わない。

## 安全性と信頼性

- 原案は不変の証拠として保存し、AI生成テキストは別フィールドにする。
- パス traversal、絶対パス、Vault 外書き込みを禁止する。
- 新規ノートのみ作成し、既存ノートの上書きは拒否する。
- Bridge の認証・HTTPS・既存の capability gate を維持する。
- 重複受付を防ぐため idempotency key / idea ID を持つ。
- 受付済み、Vault 保存済み、分析済み、承認済みを別ステータスにする。
- 自動マージ、デプロイ、HOLD解除はしない。

## 段階的な実装計画

1. 既存 LINE/Obsidian ルーティングと権限ゲートを調査する。
2. アイデアカードのスキーマと保存先を追加し、パス・上書き・重複のテストを書く。
3. 明示的な「アイデア」入力を専用ハンドラに接続する。一般メッセージを誤ってアイデア扱いしない。
4. Obsidian Bridge 経由で Vault に保存し、成功・保留・失敗を観測可能にする。
5. 関連ノート検索、分類、発展案を追加する。ローカルモデル不在時は安全に保留する。
6. CI と統合テストを確認し、ユーザー承認前はマージ・デプロイしない。

## MVP の完了条件

- 原文が欠落・改変されずに保存される。
- 同じ入力の再送で重複ノートが増えない。
- 既存ノートへの上書きと Vault 外パスが拒否される。
- Mac 停止中でも受付状態が追跡でき、後から再試行できる。
- AI分析失敗が成功扱いされず、原案は失われない。
- 生成されたアイデアから実装を始めるには明示承認が必要。
- 自動テストが通り、結果がログで確認できる。
