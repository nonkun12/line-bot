# 星を拾った夜 — 毎時シナリオ更新ループ

## 目的

毎時、次の制作・改善候補を1件だけ作り、既存の世界設定・正史・キャラクターを壊さずにレビューする。毎時の実行は「新しい正史を自動確定する」ことではない。

## 1時間ごとのサイクル

1. **Context**: シリーズ設定、全エピソード、分岐グラフ、前回のレビュー結果を読み込む。
2. **Create**: 次のエピソード、キャラクター、ロケーション、クエスト、映像カット、音楽モチーフの候補から、未着手の最優先項目を1つだけ提案する。
3. **Continuity Critic**: 固定設定、時系列、人物の動機、ID参照、分岐到達性を検査する。
4. **Game Critic**: プレイヤーの目的、選択の意味、状態変化、実装可能性を検査する。
5. **Audiovisual Critic**: 尺、カット、画面意図、音楽の感情曲線、同期点を検査する。
6. **Decision**: PASSは採用候補として別バージョン保存。HOLD/FAILは正史に反映せず、理由を記録して次回へ持ち越す。
7. **Next**: 次の1時間のタスクを1件だけ決める。

## 安全・品質境界

- 既存の正史ファイルを自動上書きしない。候補は `candidates/` 以下に別ファイルとして保存する。
- 1回の実行で生成する候補は最大1件、変更対象は許可された作品ディレクトリ内に限定する。
- 失敗時は前回の正本を維持し、実行ログに失敗理由を記録する。
- 既存設定の削除、人物の性格変更、分岐の統合、エンディング確定は人間レビューを必須とする。
- 外部公開、配信、課金、外部サービスへの投稿は行わない。
- 映像・音楽の生成ができない実行環境では、設計・レビュー・タスク準備までに留める。生成したふりをしない。
- API利用は既存の設定と利用上限の範囲内。無料枠が尽きた場合はHOLDして次回へ送る。

## 今夜の初期バックログ

1. 第1話の脚本・絵コンテ・ショットリストを検証可能なデータにする。
2. ノア、ルミナ、雨の路地のビジュアル連続性シートを作る。
3. 第2話「旧駅の案内機」のシナリオを作る。
4. 分岐グラフの状態遷移テストを作る。
5. 15秒のオリジナル音楽モチーフをMIDI/WAVで試作する。
6. 画像・映像素材の制作方式と無料で使える実行環境を検証する。

## 実行条件

GitHub ActionsのscheduleはUTCで指定する。日本時間23:00開始ならUTC 14:00に相当する。スケジュールはワークフローが既定ブランチへ取り込まれた後に有効になる。Goalの生成JOBはLINEから明示的に提案・承認されたものだけを実行する。


## 現在の実装状態（重要）

この文書の7段階ループは目標仕様であり、現行ワークフローがすべて実装済みという意味ではない。

- 現行のGitHub Actionsは、既にLINEで提案・承認されたGoal child JOBを最大1件claimし、既存のguarded development runtimeへ渡すだけ。
- 承認済みJOBがキューにない場合は「No pending Goal child JOB」で終了する。毎時必ず新しいシナリオを自動生成するわけではない。
- 現行のクラウドworkerは `agents.media.production` を呼び出さず、映像・音楽の実ファイル（MP4/WAV/MIDI）の生成・レンダリングを保証しない。
- したがって、現時点の実行範囲はシナリオ・脚本・絵コンテ・音楽設計などの候補作成まで。次段階で映像・音楽のクラウド制作アダプターを独立実装し、実ファイルを生成・検証できるようにする。
- クラウド映像JOB・音楽JOBの定期起動、成果物ハッシュ記録、Creator-Critic再検査、候補のGitHubへの安全な返却は今後の実装対象。接続前に実行済みと表示しない。
- 初回の実行には、PRのマージに加えて、LINE上でのGoal提案と本人による承認が必要。マージだけで制作JOBは自動作成されない。

### 段階的な起動条件

1. 依存PRのテストとレビューを通し、依存順に統合する。
2. LINEから「星を拾った夜」のGoalを提案し、表示された提案IDを本人が承認する。
3. まずクラウド側でシナリオ・ゲーム設計候補の1時間サイクルを確認する。
4. クラウド映像JOBと音楽JOBを別々に接続し、実ファイルの生成・検証を確認してから定期化する。Macは任意のアドバイザーとしてのみ接続する。

## Cloud-first 実行ポリシー

- 毎時のスケジュール、キュー、制作JOB、レンダリング、成果物保存はクラウド上で完結させる。
- 映像と音楽は別々のクラウドJOBとして実行し、個別に再試行・停止・レビューできるようにする。
- Macはアドバイザー専用。設計・調査・レビュー・改善提案のみを行い、制作実行や定期JOBの依存先にしない。
- Macが停止・未接続・応答なしでも、クラウド制作は継続する。
- クラウドに必要なGPU・生成モデル・容量・無料枠がない場合は、該当JOBをHOLDにする。勝手に有料サービスへ切り替えない。

## Cloud candidate producer（追加実装）

`.github/workflows/star-night-cloud-candidate.yml` は、毎時1回、承認済みGoal JOBとは独立して第1話の候補バンドルを生成する。

- 実行環境はGitHub ActionsのUbuntu runner。Macの起動・接続は不要。
- `scripts.build_star_night_cloud_candidate` が第1話の5シーン・15秒の構造化シナリオを作る。
- PythonベースでオリジナルMIDIと合成WAVプレビューを生成し、脚本・絵コンテ・ショットリスト・EDL・音楽プラン・構造Critic結果をまとめる。
- 候補はActions artifactとして14日保存する。正史や既存ファイルは更新しない。
- 現行ワークフローはBlenderとFFmpegをクラウドrunnerに導入し、構図確認用の手続き型ストーリーボード・アニマティクスMP4を生成する。これは完成映像・キャラクターアニメーション・AI生成実写ではない。
- このCriticは構造・同期の検査であり、実際の視聴・聴取や芸術的品質を保証しない。公開許可も付与しない。
- 有料APIへの自動フォールバックは行わない。

したがって、現在の実装は「毎時の候補バンドル（オリジナルMIDI/WAVと手続き型アニマティクスMP4を含む）」までであり、「完成映像の自動制作」ではない。高品質なキャラクター映像のクラウド生成は、別の検証済み生成アダプターが用意できるまで保留する。
