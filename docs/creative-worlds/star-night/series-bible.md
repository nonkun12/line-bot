# 星を拾った夜 — シリーズ設定資料 v1

> 映像短編・連作ストーリー・インタラクティブ作品・Godotゲームで共有する正本。設定を変更するときは、既存の確定事項との互換性を確認し、変更理由と移行メモを残す。

## 作品コンセプト

星の光を失いつつある未来の都市で、記憶を失った小型探索ロボット「ノア」が、地上に落ちた星のかけら「ルミナ」と出会う。ノアは街を探索し、住人たちの記憶と失われた星空を取り戻していく。物語の中心テーマは「誰かのために灯した光は、巡って自分の道も照らす」。

- ジャンル: SFファンタジー / 探索アドベンチャー / 感情ドラマ
- トーン: 静かな孤独から、発見、ぬくもり、希望へ
- 対象: 幅広い年齢層。暴力より探索・謎解き・選択を中心にする
- 映像: シネマティックな短編。光・雨・反射・シルエットを象徴として使う
- 音楽: オリジナルのピアノと柔らかな電子音を核に、物語の進行で編成を広げる
- ゲーム想定: 2D/2.5D探索アドベンチャー。Godotを第一候補とするが実装は別途検証

## 世界のルール

1. かつて都市は「星脈」と呼ばれる光のネットワークで動いていた。
2. 星脈は、星のかけら「ルミナ」を通じて記憶・感情の残響を伝える。
3. ルミナは願いを無制限に叶える魔法ではない。使うたびに小さな代償や選択が必要になる。
4. 都市の設備は完全には停止していない。探索・修理・住人との交流で少しずつ復旧できる。
5. 過去の記憶は断片として見つかるが、断片だけで全ての真実を断定しない。
6. プレイヤーの選択は「信頼」「街の灯り」「ノアの記憶」の3状態に反映する。
7. 選択に絶対的な正解は設けず、短期的な利点と長期的な影響を持たせる。

## 主な登場人物

### ノア — 主人公
- 小型の探索ロボット。丸みのある白い外装、片側に小さな傷、胸部に消えかけた星形ランプ。
- 性格: 好奇心が強く、慎重で、言葉より行動で気持ちを示す。
- 欠落: 自分が誰に作られ、なぜ記憶を失ったのか知らない。
- ゲーム役割: 探索、観察、簡単な修理、記憶の断片の再生。
- 表現ルール: 作品ごとに体格・色・傷・発光位置を変えない。

### ミナ — 整備士の少女
- 閉鎖された駅の近くで小さな修理所を守る。
- 性格: 現実的で口数は少ないが、壊れたものを見捨てられない。
- 役割: チュートリアル、修理、街の住人の情報、ノアへの信頼の変化。
- 物語上の秘密: 星脈の停止前に聞いた「空から呼ぶ声」を覚えている。

### オルド — 古い案内機
- 地下交通網に残された旧式の案内ロボット。
- 性格: 丁寧で少し融通が利かない。断片的な記録を持つ。
- 役割: 世界の歴史、地図、過去の出来事の手掛かり。
- 注意: オルドの記録は欠損しており、発言を絶対的な事実として扱わない。

### 星喰い — 未知の現象
- 生物か装置かも確定していない、光を吸収する影。
- 序盤では直接戦闘の相手にせず、環境変化・足跡・音で存在を示す。
- 正体と目的はシリーズの後半まで確定しない。

## 物語の大きな流れ

1. 発見: ノアがルミナを拾い、閉ざされた街の一部に光が戻る。
2. 探索: 駅、屋上、温室、地下水路で星脈の断片を探す。
3. つながり: ミナやオルドとの関係が、プレイヤーの選択で変わる。
4. 真相: 星脈は単なる電力網ではなく、街に暮らす人々の記憶を結ぶ仕組みだったと分かる。
5. 選択: ルミナを街全体に戻すか、失われた誰かの記憶を優先するか、別の方法を探すか。
6. 結末: 選択と探索結果に応じた複数の結末。どの結末もテーマを尊重し、単純な善悪で評価しない。

## ゲーム化の基本ループ

探索する → 手掛かりを見つける → 小さな謎を解く/修理する → 誰かと交流する → 選択する → 街と人物の状態が変わる → 新しい場所が開く。

### 永続状態（初期案）
- `trust_mina`: 0–100
- `city_lights`: 0–100
- `noa_memory`: 0–100
- `lumina_fragments`: 収集済みIDの集合
- `discovered_locations`: 解放済みロケーションIDの集合
- `choice_history`: 選択IDと選択肢IDの追記専用履歴

状態の上限・初期値・更新規則はゲーム実装前にテスト可能な仕様として確定する。

## 制作上の連続性ルール

- 新しい登場人物・場所・能力・歴史を追加するときは、この資料と矛盾しないか確認する。
- 既存キャラクターの動機を変える場合は、変化のきっかけを物語内に置く。
- 伏線は「提示」「再提示」「回収」の記録を残す。
- 映像・音楽・ゲームの各素材に同じ scene_id / character_id / location_id / event_id を付ける。
- 既存の確定設定は、Criticの承認なしに自動上書きしない。
- 毎時更新は候補の作成と評価まで。採用済みの正本は別バージョンとして保存する。
